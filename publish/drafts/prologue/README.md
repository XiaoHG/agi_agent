# 序章 为什么今天要系统学习 Agent 工程

在大模型应用快速发展的阶段，很多人第一次接触 Agent，往往是从演示视频、框架示例或一段看上去很聪明的自动化流程开始的。它们容易让人产生一种错觉，仿佛只要把模型、工具和提示词接起来，一个可用的 Agent 系统就已经成立了。但真正进入工程实践之后，这种错觉很快就会被现实打破。系统开始变复杂时，输入如何被正确路由、状态如何被保存、工具如何被约束、错误如何被恢复、结果如何被验证，这些问题会比“模型是否足够强”更早成为瓶颈。

也正因为如此，今天讨论 Agent，已经不能只停留在“它能做什么”，而必须进入“它应当如何被构建”。一个真正可持续演进的 Agent，不只是一个能生成语言的接口组合，而是一个具备执行边界、状态结构、知识链路、协议接口、协作机制和运行治理能力的系统。换句话说，Agent 的困难不在于接入模型，而在于把模型放进一个可解释、可扩展、可验证的工程结构中。

这本书的核心立场，正建立在这个判断之上。我们不把 Agent 当作一类神秘的新物种，也不把它当作若干框架概念的堆叠，而是把它放回软件工程语境中重新理解：它为什么需要输入边界，为什么需要路由与状态，为什么需要知识增强和工具协议，为什么在系统复杂之后必须引入可观测性、恢复和治理。这些问题共同定义了 Agent 工程，而不是某个单独框架的语法。

从这个角度出发，系统学习 Agent 的真正价值，不是多掌握几个名词，而是建立一种工程判断力：面对一个需求时，你应当先建立什么；当系统开始变复杂时，哪些边界必须尽早明确；当原型要迈向长期运行时，哪些能力不能再后置。这种判断力，才是未来构建专业 Agent 系统时最难替代的部分。

接下来的正文，将从最基础的问题开始：什么是 Agent，为什么它不能被简单理解为聊天机器人或普通工作流。
