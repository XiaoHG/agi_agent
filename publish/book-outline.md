# 书籍总纲

更新日期：2026-08-17

## 书籍定位

这本书不是通用的大模型入门书，也不是单纯围绕某个框架的使用手册，而是一本面向工程实践的专业 Agent 学习书籍。

全书的目标是帮助读者从真实项目出发，系统理解一个 Agent 如何从最小原型逐步演进为具备状态、工具、知识增强、多智能体协作、运行时编排、可观测性、恢复与治理能力的工业级系统。

## 目标读者

- 具备 Python 基础，准备系统学习 Agent 工程的开发者
- 已经做过 LLM 应用，但尚未形成 Agent 系统工程观的工程师
- 希望基于真实项目理解 RAG、MCP、Skills、Subagent、LangGraph 和运行时治理能力的读者

## 全书结构原则

这本书按正式技术书结构组织，而不是按项目版本顺序直接展开。

整体采用四层结构：

1. 前置部分：建立阅读上下文、读者定位和使用方式
2. 基础认知部分：建立 Agent 的概念边界和工程目标
3. 核心工程部分：围绕执行闭环、状态、知识、工具、协作、编排展开主线
4. 工业化部分：围绕可观测性、恢复、治理和系统演进收束全书

## 各部分职责

### 前置部分职责

- 解释为什么这本书存在
- 说明这本书和普通教程、框架文档、项目仓库的区别
- 帮助读者建立阅读方式，而不是直接进入细节

### 基础认知部分职责

- 解释 Agent 的概念边界
- 解释 Agent 与 chatbot、workflow、LLM app 的区别
- 解释为什么工业级 Agent 是系统工程，而不是单点功能拼装

### 核心工程部分职责

- 解释执行闭环如何建立
- 解释系统为什么需要状态、工作流、知识增强和工具协议
- 解释能力分层、多智能体协作、模型决策和结构化运行时如何进入主链路

### 工业化部分职责

- 解释为什么真实 Agent 系统必须具备可观测性、评估、恢复和治理能力
- 解释项目如何从“可运行原型”迈向“可持续演进的工程系统”

## 写作标准

- 正文第一章不从作者动机开始，而从读者必须建立的领域认知开始
- 章节顺序以知识结构和工程递进为主，不以版本时间线为主
- 项目版本、代码、测试、练习是证据材料，不直接充当书稿目录
- 每章都要兼顾概念、结构、实现、验证和工程取舍
- 全书应保持“学习书籍”而不是“项目说明手册”的表达风格
