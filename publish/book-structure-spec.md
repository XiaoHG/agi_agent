# 书稿完整结构规范

更新日期：2026-08-17

## 1. 规范目的

这份文件是 `publish/` 目录下的最高层结构规范，用来约束这本书稿的组成方式、目录职责、写作流程、证据边界和后续迭代方法。

这份规范明确一件事：当前书稿的目标不是整理项目资料，而是产出一本专业的 Agent 学习书籍。

## 2. 书稿定位

这本书是一本面向工程实践的 Agent 学习书籍，核心主题是：

- 什么是工业级 Agent
- Agent 为什么必须按系统工程方式构建
- 一个真实项目如何从最小原型逐步演进为专业 Agent 系统

因此，这本书必须同时满足四个条件：

1. 适合专业阅读，而不是内部备忘录。
2. 章节结构符合正式技术书写作逻辑，而不是版本流水账。
3. 全书结论必须能够追溯到项目版本、代码、测试和练习证据。
4. 能随着项目后续版本持续修订，而不破坏全书结构。

## 3. 正式书籍结构标准

全书必须采用“前置部分 + 正文部分 + 附录部分”的正式技术书结构。

### 3.1 前置部分

前置部分用于建立阅读上下文，不直接承担核心技术展开。

必须包含：

- 书籍简介
- 作者序
- 本书面向谁
- 如何使用本书
- 项目背景与学习路线

### 3.2 正文部分

正文部分用于承载正式知识主线，章节顺序必须服从读者学习路径和工程递进，而不是服从项目版本顺序。

正文建议结构：

- 序章 为什么今天要系统学习 Agent 工程
- 第 1 章 什么是 Agent，为什么它不是聊天机器人
- 第 2 章 工业级 Agent 的基本结构
- 第 3 章 最小 Agent 执行闭环
- 第 4 章 状态、工作流与多步执行
- 第 5 章 知识增强：RAG 如何进入 Agent 主链路
- 第 6 章 工具边界：从本地工具到 MCP 协议
- 第 7 章 能力分层：Skills、Subagent 与角色协作
- 第 8 章 模型参与决策：tool calling 与 tool loop
- 第 9 章 结构化运行时：LangGraph 与图式编排
- 第 10 章 可观测性、评估与发布门禁
- 第 11 章 恢复机制：checkpoint、run history、replay
- 第 12 章 系统治理：registry、permission 与长期演进
- 第 13 章 从学习项目到专业 Agent 系统

### 3.3 附录部分

附录部分用于承载辅助阅读资料，不应混入正文叙事。

应至少包含：

- 术语表
- 版本索引
- 练习与复盘索引
- 代码阅读索引

## 5. 目录职责规范

### `publish/drafts/`

职责：

- 存放前置部分、正文章节和附录主稿
- 不存放零散研究笔记
- 不存放审校记录

规则：

- 每个正式章节一个目录
- 当前主稿统一放在 `chNN/README.md` 或对应前置部分目录主稿中
- 不允许把“作者说明”“写作提醒”“项目管理说明”直接混进正式正文章节

### `publish/research/`

职责：

- 记录章节证据、论据和待核实问题

规则：

- 每章至少有一份证据笔记
- 研究笔记不直接替代正文
- 先补证据，再写正文

### `publish/revisions/`

职责：

- 记录章节如何变化，以及为什么变化

规则：

- 每次章节结构性修改后都要记录
- 修订记录必须指向具体主稿路径

### `publish/reference-examples/`

职责：

- 存放书稿长期参考资料
- 区分开放书稿、出版规范和官方框架文档
- 持续沉淀专业写作标准

## 6. 正文章节标准

每个正式正文章节默认应包含以下内容：

1. 章节问题或场景切入
2. 核心概念与边界说明
3. 为什么旧方案不够
4. 新结构引入了什么
5. 项目中的真实链路
6. 关键代码入口
7. 工程取舍与常见误区
8. 必要的验证命令、测试或复盘落点
9. 本章结论
10. 下一章衔接

此外，从 2026-08-17 起，所有正文章节都应逐步补齐以下固定机制小节：

- 本章代码入口
- 代码版本定位
- 本章阅读与验证指引

其中“代码版本定位”不是可选附录，而是本书的正式学习机制之一。每章都应明确告诉读者：

- 推荐切换到哪个标签
- 为什么这个代码状态适合本章学习
- 切换后优先阅读哪些代码文件
- 对应的最小验证命令是什么

## 7. 前置部分标准

前置部分不应写成技术讲义，也不应承担正文的主解释任务。

前置部分的职责是：

- 解释这本书为什么存在
- 解释本书适合谁
- 解释如何阅读、如何结合项目学习
- 解释项目背景，而不是替代正文第一章

## 8. 当前书稿重构要求

从 2026-08-17 起，当前书稿按以下原则重构：

1. 现有“为什么要把这个项目写成一本书”不再视为正文第一章。
2. 现有“最小 Agent 闭环”不再视为正文第二章，而是迁移为正式第 3 章底稿。
3. 后续必须先补前置部分和基础认知章节，再继续扩写核心工程章节。
4. 项目版本只作为证据和案例来源，不再直接主导书稿总纲。

## 9. 书稿连续性与防遗忘机制

为了防止后续新会话遗忘当前书稿标准，`publish/` 的恢复入口和执行机制必须长期固定。

强制恢复顺序：

1. `publish/current-book-summary.md`
2. `publish/book-structure-spec.md`
3. `publish/book-continuity-protocol.md`
4. `publish/chapter-map.md`
5. `publish/version-index.md`

强制同步要求：

1. 每次结构性改章，必须同步更新主稿、版本索引、证据笔记、修订记录和当前摘要。
2. 每次新增章节，必须先建立章节锚点，再开始扩写正文。
3. 每次书稿续写，都必须确认章节是否已经具备代码入口、代码版本定位和验证指引。

`publish/book-continuity-protocol.md` 是这套机制的专门文件，后续如有扩展，应优先更新该文件，而不是只在会话中口头约定。
