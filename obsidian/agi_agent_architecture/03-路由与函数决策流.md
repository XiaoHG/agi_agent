# 路由与函数决策流

## 结论

当前项目的第一层决策器是规则路由器 `route_intent()`，它先把请求分流到 `graph / tool_loop / tool_call / use_tool / workflow / direct_answer` 等大类，再由 `WorkspaceAgent` 决定是否交给 LangGraph 或 classic fallback。

## 路由决策流程

```mermaid
flowchart TD
    A[User Input] --> B[route_intent user_input]
    B --> C{显式 LangGraph 请求?}
    C -- yes --> G1[action=graph]
    C -- no --> D{显式 tool_loop 请求?}
    D -- yes --> G2[action=tool_loop]
    D -- no --> E{显式 tool_call 请求?}
    E -- yes --> G3[action=tool_call]
    E -- no --> F{RAG / MCP / Skill / Subagent / Workflow / File / Dir ?}
    F -- RAG --> T1[action=use_tool\ntool=answer_docs_with_llm / search_vector_docs / search_docs]
    F -- MCP --> T2[action=use_tool\ntool=mcp_*]
    F -- Skill --> T3[action=use_tool\ntool=list_skills / plan_skill / execute_skill]
    F -- Subagent --> T4[action=use_tool\ntool=list_subagents / plan_subagents / execute_subagents]
    F -- Workflow --> T5[action=workflow]
    F -- File/Dir --> T6[action=use_tool\ntool=read_file / list_dir / count_lines]
    F -- none matched --> Z[action=direct_answer]
```

## Runtime 决策流

```mermaid
flowchart TD
    A[ToolRoute] --> B{action}
    B -->|workflow| W{use_graph_runtime?}
    B -->|graph| G[强制走 LangGraph]
    B -->|tool_loop| L{use_graph_runtime?}
    B -->|tool_call| C{use_graph_runtime?}
    B -->|use_tool / direct_answer| N{use_graph_runtime?}

    W -->|yes| WG[_run_langgraph]
    W -->|no| WC[_run_classic_workflow]
    L -->|yes| LG[_run_langgraph]
    L -->|no| LC[_run_classic_tool_loop]
    C -->|yes| CG[_run_langgraph]
    C -->|no| CC[_run_classic_tool_call]
    N -->|yes| NG[_run_langgraph]
    N -->|no| NC[_run_classic_route]
```

## 关键函数关系

- 第一层意图识别：`agent/router.py`
- 第二层主编排：`WorkspaceAgent.run()`
- 第三层分支执行：
  - `_run_langgraph()`
  - `_run_classic_route()`
  - `_run_classic_workflow()`
  - `_run_classic_tool_call()`
  - `_run_classic_tool_loop()`

## 工程判断

- 这是“双层决策”，不是单层路由。
- 第一层负责“这是什么类型的任务”，第二层负责“用 graph 还是 classic 执行”。
- 这种设计便于后续把规则路由替换成模型路由，但不破坏主运行面。
