# v51后路线图

## 结论

`v51` 之后的路线不应该回到零散功能补丁，而应沿着“真实 runtime -> 生命周期 -> 治理 -> 交付”的主线继续推进。

## 推荐顺序

1. [[v52-异步委派队列计划]]
2. Human approval / risk-control workflow
3. Long-horizon task lifecycle
4. Externalized registry / runtime governance
5. Continuous release audit and delivery control

## 当前判断

- `v52` 是最自然的下一步
- 它会直接影响后续审批和长期任务设计

## 不建议的路线

- 回头做小功能碎片修补
- 先做 UI 或平台壳
- 把多个大主题塞进一个版本
