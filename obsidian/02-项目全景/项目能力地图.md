# 项目能力地图

## 结论

当前项目的能力层已经覆盖工业 Agent 的主干模块，但成熟度不完全一致。  
Obsidian 中应该用能力地图来区分“已经稳定的能力”和“仍在推进的能力”。

## 能力分布

### 主运行时

- LLM-first entry
- LangGraph default runtime
- workflow / tool_call / tool_loop

### 能力模块

- RAG
- MCP
- Skills
- Subagent

### 证据模块

- Trace
- Runtime Events
- Checkpoint
- Replay / Replay Diff
- Recovery / Resume

### 治理模块

- MCP governance
- Skills governance
- Release gate
- Eval matrix

## 当前成熟度判断

- 稳定主干：`agent/`、`integrations/`、`replay / recovery`
- 稳定能力：`RAG`、`Skills`、`MCP` 基础治理
- 当前迭代热点：`Subagent`
- 未来重点：`Async multi-agent runtime`
